# BasicTS 可编辑环境配置说明

**文档日期**：2026.5.16  
**配置环境**：BasicTS1.0 (Anaconda)  
**项目路径**：D:\Github\BasicTS

---

## 一、配置背景

在开发 BasicTS 项目时，需要将本地源码以可编辑模式安装到 Python 环境中，以便：
- 修改源码后立即生效，无需重新安装
- 在多个项目中共享同一份开发代码
- 方便调试和迭代开发

---

## 二、环境配置步骤

### 2.1 前置条件

- 已安装 Anaconda
- 已创建 BasicTS1.0 conda 环境
- 已克隆 BasicTS 项目到本地：`D:\Github\BasicTS`

### 2.2 配置命令

在 **Anaconda Prompt** 中执行以下命令：

```bash
# 1. 激活 BasicTS1.0 环境
conda activate BasicTS1.0

# 2. 切换到项目根目录.d.
(BasicTS1.0) C:\Users\lht12>d:

# 3. 进入项目根目录
(BasicTS1.0) D:\>cd Github\BasicTS

# 4. 以可编辑模式安装
(BasicTS1.0) D:\Github\BasicTS>pip install -e .

# 5. 验证安装
(BasicTS1.0) D:\Github\BasicTS>pip show basicts
```

## 三、原理解释

### 3.1 pyproject.toml 文件的作用

`pyproject.toml` 是 Python 项目的现代配置文件标准（PEP 517/518），用于替代传统的 `setup.py`。

#### 核心配置解析

```toml
[build-system]
requires = ["setuptools>=45", "wheel"]
```
- 定义构建系统依赖
- 告诉 pip 使用 setuptools 和 wheel 构建项目

```toml
[project]
name = "BasicTS"
description = "A Fair and Scalable Time Series Analysis Toolkit and benchmark."
requires-python = ">=3.9"
dependencies = [
    "easy-torch==1.3.3",
    "pandas",
    "numpy",
    ...
]
```
- `name`：包名称，安装后通过 `import basicts` 使用
- `dependencies`：运行时依赖，pip 会自动安装
- `requires-python`：Python 版本要求

```toml
[tool.setuptools]
package-dir = {"" = "src"}
```
- **关键配置**：告诉 setuptools 源代码在 `src` 目录
- `"" = "src"` 表示包的根目录映射到项目的 `src` 文件夹
- 因此 `src/basicts/` 就成为了 `basicts` 包

```toml
[tool.setuptools.dynamic]
version = {attr = "basicts.__version__"}
```
- 动态读取版本号
- 从 `basicts/__version__` 变量获取版本号

### 3.2 `pip install -e .` 的原理

#### 命令含义

- `-e` 或 `--editable`：以**可编辑模式**安装
- `.`：当前目录（包含 `pyproject.toml` 的目录）

#### 安装过程

**步骤1：读取配置文件**
- pip 在当前目录找到 `pyproject.toml`
- 读取 `[build-system]` 得知使用 setuptools 构建

**步骤2：解析包结构**
- 根据 `[tool.setuptools]` 的配置 `package-dir = {"" = "src"}`
- pip 知道源代码在 `src/` 目录
- `src/basichts/` 是 `basichts` 包的位置

**步骤3：创建链接（关键）**

**普通安装** (`pip install .`)：
```
site-packages/basicts/
├── __init__.py
├── launcher.py
└── ...（复制所有文件）
```

**可编辑安装** (`pip install -e .`)：
```
site-packages/basicts.egg-link
内容：D:\Github\BasicTS\src
```

核心区别：
- **普通安装**：将文件复制到 `site-packages`，修改源码无效
- **可编辑安装**：创建链接文件，指向源码目录

### 3.3 导入机制

当执行 `import basicts` 时，Python 的导入顺序：

1. 读取链接文件：
   ```
   C:\Users\lht12\Anaconda3\envs\BasicTS1.0\Lib\site-packages\basicts.egg-link
   ```

2. 链接文件内容指向：
   ```
   D:\Github\BasicTS\src
   ```

3. 最终导入：
   ```
   D:\Github\BasicTS\src\basichts\__init__.py
   ```

## 四、使用说明

### 4.1 多项目使用

**在其他项目中使用 basicts**：

只要满足以下条件，即可在任意项目中使用：
1. **激活了 BasicTS1.0 环境**
   ```bash
   conda activate BasicTS1.0
   ```

2. **在任意项目中导入使用**
   ```python
   from basicts import BasicTSLauncher
   from basicts.models.DLinear import DLinear
   ```
   
   无论项目在哪个目录（如 `D:\MyProject`、`E:\Workspace` 等），只要激活了这个环境，就能使用。

### 4.2 开发流程

**开发-测试循环**：

```bash
# 1. 修改源码（例如修改 DLinear 模型）
# 编辑：D:\Github\BasicTS\src\basichts\models\DLinear\DLinear.py

# 2. 在任意测试项目中验证（需激活 BasicTS1.0 环境）
conda activate BasicTS1.0
cd D:\MyTestProject
python test_script.py  # 会自动使用刚修改的代码

# 3. 无需重新安装，修改立即生效！
```

**可进行的工作**：

- ✓ 修改现有模型（`src/basichts/models/`）
- ✓ 添加新模型
- ✓ 修改框架功能（`src/basichts/runners/`）
- ✓ 扩展数据集支持（`src/basichts/data/`）

## 五、注意事项

### 5.1 路径依赖

**重要**：所有使用 BasicTS1.0 环境的项目都会调用 `D:\Github\BasicTS\src` 下的源码。

这意味着：
- ❌ **不能移动、删除、重命名** `D:\Github\BasicTS` 目录
- ❌ 如果移动了，所有依赖该环境的项目都会报错：
  ```python
  ModuleNotFoundError: No module named 'basicts'
  ```

### 5.2 需要移动项目时

如果必须移动项目位置：

```bash
# 1. 先卸载
pip uninstall basicts

# 2. 移动项目到新位置

# 3. 重新以可编辑模式安装
cd 新路径
pip install -e .
```

### 5.3 环境隔离

如果需要在其他电脑使用，或者不想依赖本地路径：

**方案1：发布到 PyPI**
- 开发完成后发布到 PyPI
- 用户通过 `pip install basicts` 安装独立副本
- 不依赖源码路径

**方案2：克隆后重新安装**
- 在新电脑克隆项目
- 重新执行 `pip install -e .`

## 六、常见问题

### Q1：如何确认当前使用的是本地源码？

```bash
pip show basicts
# 查看 "Editable project location" 字段
# 或在 Python 中：
import basicts
print(basichts.__file__)
# 应显示：D:\Github\BasicTS\src\basichts\__init__.py
```

### Q2：修改源码后需要重新安装吗？

不需要。可编辑模式下，修改立即生效。

### Q3：如何切换回正式版本？

```bash
# 1. 卸载本地版本
pip uninstall basicts

# 2. 安装 PyPI 正式版
pip install basicts
```

### Q4：多个开发者如何协作？

- 每个开发者克隆项目到本地
- 各自在本地执行 `pip install -e .`
- 通过 Git 同步代码修改
- 各自的环境互不影响
